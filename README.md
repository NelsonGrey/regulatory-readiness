# Regulatory Readiness Engine

**Status:** Proposed / discovery
**Baseline date:** August 30, 2026
**Working product name:** Regulatory Readiness Engine (placeholder; not trademark-cleared)

A multi-tenant platform that helps small and mid-size organizations assemble, validate, version, and export the evidence needed to prepare for a specific regulation — keeping missing, conflicting, stale, and unreviewed information visible, and never claiming legal compliance, certification, or authority approval.

The platform is **one reusable engine** plus a library of **control packs**. Each pack encodes one regulation as a dated, versioned catalog of discrete controls, with applicability rules, evidence expectations, validators, and export profiles. Adding a regulation means adding a pack — mostly data and declared rules, not a code fork.

## Current state

Full specification, a buildable monorepo, and the first slices of real engine code. `typecheck` / `lint` / `lint:copy` / `test` (180) / `build` / `format` all green.

- **Spec** — engine spec split from the origin battery package into [`docs/engine/`](docs/engine/) + [`docs/packs/espr-dpp-battery/`](docs/packs/espr-dpp-battery/) (see [ENGINE_CONCEPT.md §9](docs/ENGINE_CONCEPT.md)); pack #1 spec in [`docs/packs/eaa-accessibility/`](docs/packs/eaa-accessibility/); ADRs 0001–0005 in [`docs/adr/`](docs/adr/).
- **Scaffold** — pnpm/TypeScript monorepo (`apps/{api,worker,web,marketing}`, `packages/*`, `packs/`, `infra/`) with a local Docker dev stack (Postgres + LocalStack).
- **Marketing site** — `@rre/marketing` (Astro): public pages (home, how-it-works, platform, packs + EAA landing, pricing, security, accessibility statement, about, blog, contact, legal/*), content collections, sitemap/rss/robots. `@rre/brand` holds the design tokens the app and site share; `@rre/copy-guard` holds the forbidden-phrase list, run over rendered copy by `pnpm lint:copy` in CI. See [docs/marketing/](docs/marketing/).
- **Slice 1 so far**
  - `@rre/contracts` — pack-artifact + API request schemas (Zod).
  - `packs/eaa-accessibility/` — a `draft` bundle (20 controls, 16 applicability rules, 5 known-outcome vectors) that loads + validates.
  - `@rre/control-catalog` — `loadPack` / `validatePack` / `loadInstalledPacks`, `validateEntityFacts`, and the deterministic applicability evaluator.
  - `@rre/domain` — applicability summary, canonical-JSON, entity types, and the deterministic **readiness derivation** (`deriveControlReadiness` per control → `readinessForEntity` → `EVIDENCE_READY` / `REVIEW_NEEDED` / `BLOCKED`); browser-safe.
  - `@rre/db` — shared Postgres pool, `withTenant` (RLS `SET LOCAL`), forward-only migration runner.
  - `@rre/api` — `GET /packs` + `GET /packs/:packKey`; `POST /entities` (immutable hashed scope evaluation); `GET /entities/:id/matrix` — now with **readiness per control** (`EVIDENCED`/`MISSING`/`PENDING_REVIEW`/`CONFLICTING`/…), the approved claim value, and the entity's overall status; **`POST /entities/:id/controls/:controlKey/claims`** (assert a claim → `PENDING_REVIEW`), **`POST /claims/:claimId/decisions`** (`APPROVED`/`REJECTED`/`CLARIFICATION_REQUESTED` — a reason is required to reject; approval supersedes the prior approved claim, history preserved), **`GET /entities/:id/review-queue`**, **`GET /audit-events`** (AUD-001). Tenant via `x-tenant-id`; cross-tenant reads empty/404.
  - **Persistence** — migrations `0001` (entities + scope evaluations, RLS `FORCE`d), `0002` (`rre_app` runtime role), `0003` (append-only `audit_event` + transactional `outbox`), `0004` (`rre_relay` BYPASSRLS role), `0005` (`claim` — value immutable, only `status`/`supersedes` writable by `rre_app` — + append-only `review_decision`), `0006` (`evidence_request` + `request_item` + `access_token_grant` (no RLS — resolved by token hash) + append-only `contributor_submission` / `contributor_response_item`), `0007` (`request_draft` — one mutable row per request, overwritten on save, deleted on submit), `0008` (`expire_lapsed_requests` — a `SECURITY DEFINER` function that flips lapsed requests to `EXPIRED` cross-tenant and writes their audit + outbox trail), `0009` (append-only `readiness_snapshot` — the frozen canonical export document + its content hash), `0010` (`notification` — per-tenant feed; only `read_at` is mutable to `rre_app`), `0011` (`document` — immutable key/hash/size, only lifecycle columns mutable, never hard-deleted — + append-only `document_association`); `pnpm db:migrate`.
  - **Unit of work** (ADR 0004) — `pgUnitOfWork` / `inMemoryUnitOfWork`: business writes + the audit event + outbox messages commit in **one tenant-scoped transaction** or not at all.
  - **Outbox relay + events consumer** — `@rre/worker` drains unpublished `outbox` rows (`FOR UPDATE SKIP LOCKED`) and publishes them to SQS (`@aws-sdk/client-sqs`, LocalStack in dev); success sets `published_at`, failure bumps `attempts` and retries (at-least-once). A second loop, the **events consumer**, reads that queue, maps operator-facing events (`request.submitted` / `request.expired` / `entity.readiness_snapshot_created`) to `notification` rows (written as `rre_app` under the event's tenant), and best-effort delivers them to Slack (`SLACK_WEBHOOK_URL`) or the log. A message is `DeleteMessage`d only after its handler succeeds; a delivery failure doesn't lose the row.
  - **Operator web** — `@rre/web` (React + React Router): a control-pack list; **`ENT-001`** create screen whose scope-fact form is generated from `GET /packs/:packKey`; **`MAT-001`** matrix screen — entity-status banner (`BLOCKED` / `REVIEW_NEEDED` / `EVIDENCE_READY`), an honest denominator (never a %), applicability **and readiness** per control, the approved value, a clickable readiness-count filter, and an inline "add a claim" form (asserts → review, not approved); a **review queue** screen that approves / rejects (reason required) pending claims. Dev proxy `/api → :3000`.
  - **Slice 3 — contributor request loop** (`REQ-*` operator side + `SUP-*` no-account portal)
    - `@rre/api` operator routes: **`POST /entities/:id/requests`** (pick applicable controls, mint a request → returns the plaintext token **once** + `contributorPath`), **`GET /entities/:id/requests`**, **`GET /requests/:requestId`** (items, grant prefixes/uses, submission history — never the token), **`POST /requests/:requestId/send`** / **`/revoke`** / **`/resend`** (reissue — revoke live grants, mint a fresh link, reactivate a lapsed request), **`POST /submissions/:submissionId/items/:itemId/accept`** (pull one contributor response into the review queue as a `SUPPLIER_ASSERTION` `PENDING_REVIEW` claim).
    - **`/contributor/v1`** portal — the token is the principal, no tenant header; `referrer-policy: no-referrer`, `cache-control: no-store`, `x-robots-tag: noindex, nofollow` on every response. **`GET /requests/:token`** shows only the requested controls + the entity name (and any saved draft); **`PUT /requests/:token/draft`** saves in-progress answers (mutable, one per request); **`POST /requests/:token/submit`** takes an availability state per item, writes an immutable submission version, clears the draft, flips the request to `SUBMITTED`, and returns a receipt (`rcpt_…`). Invalid / expired / revoked tokens all return the same generic `INVALID_LINK`.
    - **Notifications** — `request.created` / `request.sent` / `request.revoked` / `request.submitted` / `request.link_reissued` / `request.expired` go through the same transactional outbox → relay → SQS path as readiness events, so downstream notifiers stay decoupled.
    - **Expiry sweep** — `@rre/worker` runs `sweepExpiredRequests()` on a timer (default 60s): requests with no unrevoked, unexpired grant move from a non-terminal status to `EXPIRED`, each with its own audit event + `request.expired` notification, all in one transaction. The cross-tenant transition is a `SECURITY DEFINER` function; the worker connects as `rre_app` holding only `EXECUTE` on it — `rre_relay` stays minimal.
    - Tokens are 192-bit, stored **hashed only** (sha256) with an 8-char lookup prefix; `access_token_grant` deliberately has no RLS and is resolved by hash **before** the tenant is known, then every downstream write runs under the resolved tenant's RLS.
    - **Web** — operator `RequestsPage` (`/w/entities/:id/requests`): pick applicable controls, set a message + link expiry, create a request, and see the contributor URL **once** with a copy button; `RequestDetailPage` shows status + grant prefix/uses, "draft in progress" if the contributor has started, requested controls, and each submission with an "accept into review" action per supplied value; can mark sent / revoke / **reissue** the link (new URL shown once). Contributor `ContributorPortalPage` (`/contribute/:token`) is served **outside** the operator shell — no workspace chrome; it shows only the requested controls, an availability state + value per item, a **Save progress** button that PUTs a draft (and rehydrates from it on return), no account needed, and a receipt on submit. Invalid / expired links get one generic message.
  - **Slice 4 — readiness snapshot + export**
    - `@rre/domain` `buildCanonicalExport()` — pure, deterministic (controls sorted by key, byte-stable `canonicalJson`), browser-safe. Produces the canonical export document (engine TRD §14.1): pack + source metadata, entity + classification facts, frozen evaluation reference, a verdict mapped from the entity status (**never** "compliant" / "certified"), readiness counts, per-control (clause, WCAG SC, applicability, readiness, approved claim), and an **exceptions** list = every required control not yet `EVIDENCED`. `canonicalExportToCsv()` renders the control matrix.
    - `@rre/api` — **`POST /entities/:id/readiness-snapshots`** freezes the current readiness into an append-only `readiness_snapshot` (canonical document + `sha256:` content hash), audits `readiness_snapshot.created`, enqueues `entity.readiness_snapshot_created`; **`GET`** list + detail; **`GET /readiness-snapshots/:id/export.json`** / **`export.csv`** return the document as an attachment, generated only from the frozen snapshot. A later claim approval never changes an existing snapshot — a new snapshot has a new hash.
    - **Web** — `SnapshotsPage` (`/w/entities/:id/snapshots`): "Create readiness snapshot", a list with status + content hash, and JSON / CSV downloads (fetched via `api.getText` and saved client-side, so no auth-header problem on a plain link).
  - **Slice 5 — notifications**
    - `@rre/worker` — `eventToNotification()` (pure map from a domain event to a notification, `null` for the operator's own actions and plumbing); `consumeEventsOnce()` (drain a batch from the events queue, handle-then-ack, leave a failing message for redelivery, drop an unparseable one); `pgNotificationWriter` writes rows as `rre_app` under the event's tenant; `slackWebhookNotifier` / `consoleNotifier` for external delivery.
    - `@rre/api` — **`GET /notifications`** (`?unread=1`, `?limit=`), **`GET /notifications/unread-count`**, **`POST /notifications/:id/read`**, **`POST /notifications/read-all`**. Read + mark-read only; the rows are written by the worker.
    - **Web** — `NotificationsPage` (`/w/notifications`) with per-item "Mark read" + "Mark all read" and a deep link to the request/snapshot; the `Shell` nav shows an unread badge, refreshed on navigation.
  - **Slice 6 — document intake + evidence store**
    - **`ObjectStore`** port — `createLocalObjectStore()` (bytes in memory, served by the API's own `/documents/content/*` route; the default for dev, tests, CI) and `createS3ObjectStore()` (presigned PUT into a quarantine bucket, `CopyObject` promote into originals, presigned GET — the ARCHITECTURE_AWS §4 shape). Selected by `S3_BUCKET_ORIGINALS` + `S3_BUCKET_QUARANTINE`.
    - **migration 0011** — `document` (RLS-scoped; the object key, hash, size, media type are immutable — only the lifecycle columns move, and rows are never hard-deleted) + append-only `document_association`.
    - **`@rre/api`** — **`POST /documents`** (validate media type + size, create an `UPLOADING` row, return a presigned/relative PUT URL), **`POST /documents/:id/finalize`** (fetch the bytes, SHA-256 them, run `scanBytes()` — media-type allow-list + size ceiling + EICAR — then promote quarantine→originals and set `AVAILABLE`, or `REJECTED_MALWARE` / `UNSUPPORTED`; audit + enqueue `document.available` / `document.rejected`), **`GET /documents`** (`?entityId=`), **`GET /documents/:id`**, **`GET /documents/:id/download`** (a URL only when `AVAILABLE`), **`POST /documents/:id/associations`**. A quarantined object is never downloadable.
    - **Web** — `DocumentsPage` (`/w/entities/:id/documents`): pick a file → initiate → PUT bytes → finalize; a list with status, size, and SHA-256; a client-side download for `AVAILABLE` documents.
  - **Testing** — 180 tests / 44 projects. Unit: readiness derivation (every precedence branch + entity-status roll-up), claim assert/approve/reject/supersede + reason enforcement, uow atomicity + audit pagination, applicability evaluator, pack validation, capability matrix, SQS command shape, request-loop token hashing + not-applicable-control rejection + expired-grant handling, draft round-trip + overwrite + clear-on-submit + outbox notification, resend (old link dies / new link works / reactivates a lapsed request / refuses a closed one); web screens (form from schema, matrix banner + readiness column + filter + inline claim + refetch, review-queue approve/reject with reason + server-error surfacing, request builder offering only applicable controls + one-time link reveal, request detail accept-into-review + revoke + reissue, contributor portal least-disclosure + no-account submit + generic invalid-link message + draft rehydrate + save-progress). Integration (Postgres, `TEST_DATABASE_URL`, else skipped): RLS hides cross-tenant rows (entities, audit, claims, review decisions, requests, submissions, drafts) entirely; `WITH CHECK` rejects cross-tenant inserts; grants resolve by hash with no tenant context; `request_draft` is RLS-scoped **and** mutable (upsert overwrites, delete clears); the expiry sweep flips only lapsed non-terminal requests and writes their audit + outbox trail, cross-tenant, idempotently; a failed uow rolls back the entity **and** its audit event; `audit_event` / `review_decision` / `contributor_submission` `UPDATE`/`DELETE` denied to `rre_app`; `claim.value` is immutable to the app; the relay and the expiry sweep each run in their own disposable database; `readiness_snapshot` and `notification` are RLS-scoped, and `UPDATE`/`DELETE` are denied to `rre_app` (only `notification.read_at` is writable). Worker unit tests cover the event→notification mapping, `handleEvent` (row written even when external delivery throws), and the consumer's ack/redelivery/drop behaviour. `scanBytes` covers empty / oversize / disallowed-type / EICAR; `document` + `document_association` are RLS-scoped with only the lifecycle columns mutable and no association deletes. **UAT** (`apps/api/src/acceptance/`): `AC-003`, `AC-004`, `AC-006`/`AC-007` (least-disclosure contributor link + no-account submission), `AC-010`, `AC-016` (upload → scan → available → download; malware quarantined; unsupported type rejected), `AC-018`, `AC-021` (snapshot freeze + export-only-from-snapshot + immutability + no forbidden language).

Next: link documents to claims as evidence (`ClaimEvidenceLink` + `EvidenceLocation`) and gate `EVIDENCED` on evidence presence, then AI/OCR extraction proposals.

Next: contributor draft-save (`PUT /contributor/v1/requests/:token/draft`), and request notifications through the outbox.

## Proposed first pack

**EAA accessibility readiness.** Largest live market (EU Accessibility Act enforcement in force since June 2025), strong willingness to pay, soft mid-bottom competitive layer. The engine is built against this pack first; **CRA** (Cyber Resilience Act) is the proposed second pack, chosen to prove the pack abstraction on a very different domain.
